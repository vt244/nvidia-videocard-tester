# Проверка NVIDIA CUDA GPU

Проект определяет GPU через NVIDIA Driver API, подбирает образ CUDA, собирает тесты под их compute capability и запускает проверку памяти и вычислений. Подходит для разного объёма памяти, разных поколений и смешанных наборов карт. На каждой GPU работает отдельный контейнер, выбранный по UUID; внутри него карта имеет индекс `0`. Ограничение числа устройств внутри `cuda_memtest` не ограничивает число проверяемых карт на хосте.

Требования: Linux, Python 3.8+, Docker, NVIDIA Container Toolkit и рабочий драйвер, поддерживающий установленные GPU. Драйвер на хосте проект не устанавливает. Перед запуском освободите выбранные карты от графических и вычислительных задач. Сценарий откажется от запуска при уже работающей диагностике, вычислительных процессах или более 128 МиБ занятой памяти на выбранной карте.

## Запуск

```bash
cd video-test
./run-tests.sh --plan           # Только обнаружение и план, без нагрузки
./run-tests.sh --build-only     # Собрать образы, без нагрузки
nohup ./run-tests.sh > launch.log 2>&1 < /dev/null &
```

Сборка выполняется автоматически при отсутствии соответствующего образа. После изменения Dockerfile, скриптов внутри образа или исходников используйте `--rebuild`. Слои образов хранятся в Docker, результаты — в каталоге `results/` в корне проекта.

```bash
./run-tests.sh --gpus 0,2 --seconds 1800
./run-tests.sh --gpus GPU-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx --smoke
./run-tests.sh --passes 2 --iterations 1000 --memory-timeout 7200
./run-tests.sh --temperature-limit 80 --burn-memory 85
```

Без параметров: все карты; один проход тестов памяти 0–8 и 10, 100 итераций для тестов 0/10, ограничение времени этапа памяти 1800 секунд, затем `gpu-burn` на 900 секунд с 90% доступной памяти. `cuda_memtest` пытается выделить максимум доступной ему памяти и уменьшает объём при отказе выделения; фактический объём записывается в журнал. Часть VRAM занята драйвером и CUDA, поэтому весь физический объём проверить таким способом нельзя. Длительный тест удержания данных (№9) по умолчанию отключён.

`--smoke` проверяет запуск: 64 МиБ памяти, тест 10 с одной итерацией, затем 5 секунд `gpu-burn`. Это не полный тест исправности. Размер матриц для `gpu-burn` подбирается по объёму VRAM, чтобы карты с небольшим объёмом памяти могли выполнять проверку. Сравнение результатов выполняется и на небольших картах.

## Совместимость

Один готовый CUDA-образ не поддерживает все поколения NVIDIA. Проект выбирает профиль для каждой карты, учитывая максимальную версию CUDA Driver API. В образ попадает нативный код `sm_XX`; сборка не полагается на совместимость PTX с будущими картами.

| Compute capability | Автоматический профиль |
|---|---|
| 2.0 / 2.1 (Fermi) | CUDA 8.0, Ubuntu 16.04 (`nvcr.io`) |
| 3.0 / 3.2 (ранние Kepler) | CUDA 10.2, Ubuntu 18.04 (`nvcr.io`) |
| 3.5 / 3.7 (Kepler) | CUDA 11.8, либо более старый профиль при старом драйвере |
| 5.x–9.0 из списка поддерживаемых архитектур | CUDA 12.4, либо 11.8/10.2/8.0 при необходимости и совместимости |
| 10.0 / 10.1 / 10.3 / 12.0 | CUDA 12.9; для совместимых архитектур и более старого драйвера — CUDA 12.8 |
| 11.0 / 12.1 | CUDA 13.0 |

Для нового поколения или другого драйвера можно явно задать devel-образ:

```bash
./run-tests.sh --cuda-image nvidia/cuda:13.0.2-devel-ubuntu22.04 --rebuild
# Или: CUDA_IMAGE=... ./run-tests.sh
```

Компилятор и CUDA runtime проверяют совместимость выбранного образа с GPU. Если архитектура не поддерживается, сценарий сообщает об ошибке; это не считается успешным тестом. CUDA 1.x, MIG-инстансы и Jetson/L4T этим сценарием не поддерживаются. Windows требует отдельного окружения Linux/WSL с поддержкой GPU. Для CUDA 8.0/10.2 используется официальный реестр `nvcr.io`: соответствующие теги на Docker Hub недоступны. Наличие этих манифестов проверено 2026-10-30; доступность архивных образов и совместимых драйверов в будущем не гарантируется. Совместимость каждого профиля со всеми соответствующими моделями GPU не проверена на физическом оборудовании. Обещать поддержку любой когда-либо выпущенной CUDA-карты нельзя.

В сборке адаптированы вызов CUDA kernel (`cuLaunchKernel`), отключение Tensor API для CUDA 8 и размер матриц. Tensor-режим не включён: базовая проверка использует FP32 и не требует Tensor Cores.

Основания: [спецификация сборки gpu-burn](https://github.com/wilicc/gpu-burn), [CUDA 12.9: поддержка Maxwell/Pascal/Volta в ветке 12.x](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-toolkit-release-notes/index.html), [исходники cuda_memtest](https://github.com/ComputationalRadiationPhysics/cuda_memtest).

## Результаты и остановка

```bash
cat results/latest/plan.json
cat results/latest/status.txt
tail -f results/latest/gpu-0/memtest.log
tail -f results/latest/gpu-0/gpu-burn.log
tail -f results/latest/telemetry.csv
docker ps --filter label=video-test.managed=true
# Остановить конкретную карту (имя из docker ps):
docker stop -t 10 video-test-ДАТА-ВРЕМЯ-gpu0
```

Журналы сохраняются в `results/<дата-время>/gpu-<индекс>/`, вместе с кодами завершения и статусом `PASSED` или `FAILED`. Общий `status.txt` появляется после завершения. Ошибка или неполный тест одной карты останавливает остальные контейнеры этого запуска. Проверяются коды завершения, ошибки в журналах и итоговые признаки завершения; в частности, `gpu-burn` должен явно сообщить `GPU 0: OK`. Контейнеры сохраняются для разбора; удаляйте завершённые контейнеры вручную, результаты останутся на хосте.

Телеметрия снимается каждые 5 секунд для всех GPU, контролируются выбранные карты. Температура ядра от 85 °C, исчезновение карты или недоступность температуры/опроса останавливают запуск. SIGINT/SIGTERM сценарию также останавливает его контейнеры. Температура памяти доступна не на всех картах и этим монитором не контролируется. Это программный контроль, не аппаратная гарантия. Драйвер, частоты и лимиты мощности сценарий не изменяет.

Успешный тест не доказывает полную исправность всех узлов карты. Проверка Xid/AER по системному журналу в сценарий не входит.

## Проверка проекта

```bash
python3 -m unittest discover -s tests -v
# Интеграционные проверки обработчика результатов без нагрузки на GPU:
VIDEO_TEST_IMAGE=ИМЯ_СОБРАННОГО_ОБРАЗА python3 -m unittest discover -s tests -v
bash -n run-tests.sh build-tools.sh container-tests.sh
./run-tests.sh --plan
./run-tests.sh --build-only --rebuild
# На свободных GPU:
./run-tests.sh --smoke
```

`.gitignore` исключает результаты, логи, локальные резервные копии, `.env`, Python cache и бинарники. Исходники тестов не исключены.
